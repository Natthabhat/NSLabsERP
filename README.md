# NS Labs ERP

Next.js workspace at https://erp.ns-labs.com for NS Labs expenses, filament, sales and marketplace payouts.

## PostgreSQL backend

Production uses the existing database named "ns labs". The app does not import or copy spreadsheet records.

| Screen | Existing table |
| --- | --- |
| Costs & production | public.printing_expenses |
| Filament inventory | public.filament_purchases |
| Stock movements | public.st_sales_log |
| eBay / Etsy / Lazada / Shopee | public.platform_payouts, filtered by platform |

Click a cell to edit it directly in the table. Enter saves, Escape cancels, and the check/cancel buttons support pointer or touch use. Text, number, date, dropdown and checkbox fields use the same inline workflow. Errors stay beside the cell, and calculated values remain read-only.

Screens without PostgreSQL tables are hidden in database mode. Expense and filament totals are generated by PostgreSQL and read-only. This release reads, searches, paginates and edits existing records; it does not insert or delete records.

Website sign-in verifies the configured PostgreSQL user with a short-lived database connection. The password is not retained. A seven-day encrypted, HTTP-only, Secure session cookie identifies the user. Only POSTGRES_LOGIN_USER can sign in, with a global per-process limit of ten attempts per minute. Data APIs require a database session, and writes require the APP_URL origin.

The server uses a separate nslabs_erp_web role with SELECT and column-specific UPDATE permissions on the four tables. It has no superuser, schema creation or deletion privileges. Each edit locks the row, compares its PostgreSQL version and records the change in erp_web.edits in the same transaction. Persistent operation IDs make retries idempotent across app restarts. The audit table stores before/after values and needs the same backup and retention protection as the database.

## Configuration

Create .env.production on Ubuntu with:

    DATA_BACKEND=postgres
    DATABASE_URL=postgresql://nslabs_erp_web:YOUR_PASSWORD@postgresql:5432/ns%20labs
    POSTGRES_LOGIN_USER=natthabhat
    APP_URL=https://erp.ns-labs.com
    SESSION_SECRET=GENERATE_A_RANDOM_SECRET_OF_AT_LEAST_32_CHARACTERS

Keep environment files outside Git and Docker images. Compose connects to the external nslabs-db-admin network where the hostname is postgresql. Port 3400 binds to server loopback and LAN address 192.168.31.36. Cloudflare routes the HTTPS domain to that service.

Back up the database before initial provisioning. On Ubuntu, scripts/configure-postgres.py creates the restricted role, applies sql/001-postgres-access.sql and saves its generated password directly to the server environment file without printing it. It preserves existing configured database credentials. The migration adds an audit schema and grants; it does not alter the original data tables. The script assumes container postgresql and administrator natthabhat.

    docker compose up -d --build
    docker compose ps
    docker compose logs --tail=100 erp

The container runs as non-root node with all Linux capabilities dropped, automatic restart and an HTTP health check. The optional no-new-privileges setting is omitted with owner approval because this Ubuntu host denies executable startup with it enabled.

## Development and checks

    npm ci
    npm test
    npm run build
    npm run dev

Use .env.local with the above variables, a reachable database address and APP_URL=http://localhost:3000 for development. Integration tests run only with TEST_DATABASE_URL pointing to disposable database nslabs_erp_test. Never point them at production. They verify persistence, generated totals, stale edits, duplicate operations, rollback, platform isolation, permissions and credential verification.

## Google Sheets mode

The original adapter remains available with DATA_BACKEND=sheets and the Google OAuth variables in .env.example. It reads and edits the configured workbook through the Sheets API. Export or synchronization from PostgreSQL is not implemented. Demo records are fictional and temporary.
